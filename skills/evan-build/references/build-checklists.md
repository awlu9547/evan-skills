# Evan Build 接力模板、审查细则与 PR 收口清单

在更新阶段交接快照、执行 Open Code Review、触发跨线程接力或做最终阶段 PR 收口时按需读取本文件。

## 一、5 行阶段交接快照模板（回写至仓库外 `PLAN.md`）

每阶段完成 `git commit` 后，在 `PLAN.md` 的“阶段交接记录”下追加本阶段快照：

```markdown
### 阶段 <N> 交接快照（<已完成 | 阻塞>）
- 锚点与提交: 分支 `<branch>` | worktree `<abs-path-or-root>` | HEAD `<short-sha>`（本阶段提交）
- 改动偏差: <与计划强相关文件清单完全一致 | 补改了 `path:symbol`，原因：...>
- 关键裁决: <无 | 裁决：<决定> — <原因> — <影响>>
- 验证与审查: <已通过命令与退出码 0、OCR 结论>；未验证项：<无或具体原因>
- 交接给下一阶段（≤3 条）: <新定内部契约 / 已复用符号 / 需避开的坑，无则写无>
```

## 二、Open Code Review 判定细则

1. **工具选择** 优先加载 `open-code-review` skill 调用本机 `ocr` CLI（不是 MCP 工具，也不在仓库 npm script 中）；仅在 skill 无法加载或外部 OCR 模型不可连时降级 `open-code-review-delegate`。
2. **问题分级处理**
   - `critical` / `high` / 明确影响行为的 `medium`：统一汇总、集中修复、重跑受影响测试。
   - 低优先级 / 误报 / 超出本阶段范围：在交接快照中记录判断依据，不为单个问题额外重开审查。
3. **复审边界（单阶段硬上限 2 次）**
   - 默认每阶段仅做 1 次 OCR，常规修复经最新测试通过即可进入提交。
   - 仅当修复改动触及**核心对外接口、安全权限、并发正确性、或持久化/数据一致性**时，才对本阶段完整差异触发最多 1 次复审。
   - 复审发现的明确阻塞项集中修复并重测后直接进入提交，不再启动第 3 次审查；非阻塞项记为剩余风险。
4. **失败停点** 审查工具不可用、必要验收未通过或存在阻塞问题时，将 `PLAN.md` 本阶段状态置为 `阻塞`，写明原因与恢复步骤后停下，保留当前实际进度。

## 三、跨线程接力协议（T3 高优先级 + 非 T3 降级）

### 触发前提
- 本阶段所有业务代码与测试已 `git commit`（从规划线程首切阶段 1 时，只需 `PLAN.md` 已 `FROZEN` 且 worktree 就绪、无半成品业务修改）。
- 本阶段 5 行交接快照已落盘到仓库外 `PLAN.md`。
- 当前无任何阻塞状态。

### 1. T3 Code 自动接力（最高优先级）
1. 调用 `t3_worktree_status` 核对当前分支与工作区绝对路径。
2. 调用 `t3_thread_launch` 启动新顶层线程：
   - 在 worktree 中必须传 `workspaceStrategy: { type: "existing_worktree", worktreePath: "<abs-worktree-path>" }`。
   - 在原仓库根目录则传 `workspaceStrategy: { type: "root" }`。
3. 交接 `message` 只放极简指针（不长篇复述历史）：
   - 加载 `$evan-build`
   - `PLAN.md` 绝对路径
   - 刚完成的提交短哈希（若有）与阶段交接快照已更新
   - 剩余待执行阶段范围与推进模式（默认连续跑完，或单阶段汇报模式）
   - 明确转达用户已授权按 `PLAN.md` 为剩余阶段开启新顶层线程接力
   - 最多 3 条未落盘临时注意事项（如有）
4. 在当前线程附上新线程链接后立即结束。

### 2. 非 T3 harness 降级接力提示词模板
在 Claude Code、Pi、终端 CLI 等无 `t3_thread_launch` 的环境触发换会话接力时，直接输出以下可复制块：

```text
$evan-build 继续执行计划
- PLAN.md: <abs-plan-path>
- 工作目录 / worktree: <abs-worktree-path>（分支 `<branch>`，当前 HEAD `<short-sha>`）
- 待执行阶段: 阶段 <next> 至 阶段 <end>（已更新阶段 <prev> 交接快照，先做双重真值核对后连续推进）
- 注意事项: <≤3 条，无则省略>
```

## 四、最终阶段 PR 交付摘要模板与收口清单

### 收口核对清单
- [ ] 全部阶段进度表均为 `已完成` 且已填入真实提交短哈希
- [ ] 受影响范围的类型检查与 Lint 已基于最新提交跑通
- [ ] `git merge-tree` 对最新参考分支只读预检无冲突（若有冲突说明涉及文件）
- [ ] 已对照参考分支完成 1 次整分支 Open Code Review（`--from <base> --analysis`）
- [ ] 确认本地 `PLAN.md` 未进入任何 commit 与暂存区

### 可直接粘贴的 PR 交付摘要模板

```markdown
## 背景与目标
<1~2 句话说明解决的问题或新增的能力>

## 根因与关键设计取舍
- <修复类写本质根因与治本方案；新增/优化类写核心设计与二三阶影响应对>
- <关键复用与最小改动说明>

## 影响范围与兼容保护
- 涉及模块与核心文件: <列出强相关模块与主要文件>
- 跨模块契约与存量兼容: <说明对同事模块接口、老数据、缓存与默认配置的影响及保护>

## 验证结果
- 自动化检查: <实际执行的测试、类型检查、Lint 命令与结果>
- 人工验收与审查: <人工验收结论、整分支 Open Code Review 结论、`git merge-tree` 冲突预检结果>

## 剩余风险与待人工确认项
- <无，或逐条列出具体风险与建议关注点>
```

### 最终分支收口动作（等用户确认后执行）
- **功能分支起点** 确认目标功能分支工作区干净 → 本地合并本次临时分支 → 核对合并结果与提交历史 → 删除本次新建的临时分支及 `~/.t3/worktrees/<repo>/<task-slug>` worktree。
- **主分支起点** 按用户单独授权执行 `git push` 与创建 PR → 待 PR 合入后再清理分支与 worktree。
