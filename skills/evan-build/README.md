# `evan-build` 技能

[English](README_EN.md)

`evan-build` 用于严格按照已定稿冻结（`状态: FROZEN`）的仓库外 `PLAN.md` 连续实施开发阶段，完成 worktree 自动落地、强相关 Diff 复核、测试回归、受控 Open Code Review、纯业务中文提交、5 行交接快照回写、T3 优先跨线程接力及最终 PR 收口。

## 适合用它做什么

- 默认按顺序一次性连续跑完全部阶段，每阶段独立验收提交，仅在用户要求“每阶段跑完汇报”或指定单阶段时中途停下。
- 强制“改码必重测”：每次修复（含审查后修改）都基于最新代码重跑验收与回归命令并核对实际输出。
- 提交前强制执行 `git diff --stat` 对照 `PLAN.md` 强相关文件清单，并完成受控的 Open Code Review（默认 1 次，高风险改动最多 1 次复审）。
- 只提交纯业务代码与测试，提交后将真实短哈希、五态进度与 5 行交接快照写回仓库外 `PLAN.md`，绝不把计划文件带进 Git 提交。
- 优先使用 T3 Code 新建干净顶层线程连续接力（非 T3 环境输出可复制极简接力提示词），末阶段执行 `git merge-tree` 冲突预检、整分支审查并输出可直接提 PR 的交付摘要。

## 工作方式

1. **校验计划、落地 worktree 与双重核对**：确认 `PLAN.md` 为 `状态: FROZEN`；阶段 1 按计划自动在 `~/.t3/worktrees/<repo>/<task-slug>` 创建新分支和 worktree；后续阶段用“5 行交接快照 + Git 真实 `HEAD`”双重核对后起步。
2. **单线程实施、强相关 Diff 与硬验证**：按计划最小改动实施，执行 `git diff --stat` 核对无无关修改后运行验收与跨模块回归，改码必重测。
3. **审查、纯业务提交与连续接力**：执行 1 次 Open Code Review 并集中修复阻塞，使用简体中文做纯业务 `git commit`，回写真实短哈希与 5 行交接快照到仓库外 `PLAN.md`，优先在 T3 自动开新线程连续推进；末阶段输出 PR 摘要并等用户确认后再合回/删临时分支或推远端提 PR。

## 典型请求

- “按 `~/.t3/plans/<repo>/<slug>/PLAN.md` 开始实施。”
- “按计划执行，每阶段跑完结束跟我汇报。”
- “核对 `PLAN.md` 交接快照，继续完成剩余阶段并准备 PR 摘要。”

## 你需要提供

- 状态为 `FROZEN` 的 `PLAN.md` 路径。
- 如需每阶段停下汇报或只跑特定阶段，可显式说明（未说明则默认连续跑完）。
- 最终本地合回删临时分支，以及推送远端、提 PR 需等你确认后再执行。

## 产出

- 对应阶段的纯业务代码与测试提交（简体中文提交信息）。
- 更新后的仓库外 `PLAN.md`（包含五态进度、真实短哈希、关键裁决与 5 行交接快照）。
- T3 接力场景下的新顶层线程链接（非 T3 环境为极简接力提示词），以及末阶段可直接粘贴提 PR 的交付摘要。

## 边界

- 不接受未定稿（非 `FROZEN`）的计划；缺计划或发现接口/验收条件变更时，会暂停并交回 `evan-plan`。
- 不自动执行未经单独授权的 `git push`、合并 PR 或线上部署。
- 代码审查默认调用 `open-code-review`（本机 `ocr` CLI）或回退 `open-code-review-delegate`；线程接力依赖 T3 Code 的 `t3_worktree_status` / `t3_thread_launch` 工具，在普通终端或无对应工具的 Agent 中可按单线程模式手动开新会话继续。

## 相关技能
