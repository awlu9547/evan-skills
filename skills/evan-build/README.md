# `evan-build` 技能

[English](README_EN.md)

`evan-build` 用于严格按照已定稿（`状态: FROZEN`）的 `PLAN.md` 实施指定开发阶段，在单线程编码、硬验证、Open Code Review 审查修复与阶段提交之后，支持跨阶段开新线程接力与最终整分支收口。

## 适合用它做什么

- 按 `PLAN.md` 的阶段边界逐段实施代码改动，防止范围蔓延或偏离已确认设计。
- 强制“改码必重测”：每次修复（含审查后修改）都基于最新代码重跑验收与回归命令并核对实际输出。
- 在每阶段提交前对完整差异执行受控的 Open Code Review（默认 1 次，高风险改动最多 1 次复审，杜绝无限审查循环）。
- 同步更新 `PLAN.md` 的进度表、提交标识与轻量实现裁决记录。
- 在多阶段或重上下文任务中，通过新建干净顶层线程接力实现抗上下文腐烂，并在最终阶段做 `git merge-tree` 冲突预检与整分支收口审查。

## 工作方式

1. **校验计划与 Git 起点**：确认 `PLAN.md` 为 `状态: FROZEN` 且前置阶段已验收，核对当前分支、worktree 与参考分支变化。
2. **单线程实施与硬验证**：沿计划入口实现并补充测试，私有小微调直接裁决记账，每次改码后重跑完整验收命令。
3. **审查、提交与收尾**：执行 1 次 Open Code Review 并集中修复阻塞问题，验证通过后只提交本阶段改动并更新 `PLAN.md`；若仍有已授权阶段且配置了接力模式，可自动开启干净新线程继续；末阶段额外执行合并预检与整分支收口审查。

## 典型请求

- “按 `PLAN.md` 执行第 1 阶段。”
- “继续按计划执行第 2 和第 3 阶段。”
- “恢复上个阶段的开发并完成收口。”

## 你需要提供

- 状态为 `FROZEN` 的 `PLAN.md` 路径。
- 明确授权执行的阶段编号（单阶段或多阶段）。
- 如涉及最终合并、推送或部署，需给出明确的单独授权。

## 产出

- 对应阶段的代码与测试实现，以及受控的 Git 阶段提交。
- 更新后的 `PLAN.md`（包含阶段状态、测试与审查摘要、提交标题标识及关键裁决记录）。
- 接力场景下的新顶层线程交接链接（若开启换线程接力）。

## 边界

- 不接受未定稿（非 `FROZEN`）的计划；缺计划或发现接口/验收条件变更时，会暂停并交回 `evan-plan`。
- 不自动执行未经单独授权的 `git push`、合并 PR 或线上部署。
- 代码审查默认调用 `open-code-review`（本机 `ocr` CLI）或回退 `open-code-review-delegate`；线程接力依赖 T3 Code 的 `t3_worktree_status` / `t3_thread_launch` 工具，在普通终端或无对应工具的 Agent 中可按单线程模式手动开新会话继续。

## 相关技能
