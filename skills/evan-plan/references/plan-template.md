# 企业级 PLAN.md 模板与门禁核对清单

在撰写 `PLAN.md`（或双方案中的 `PLAN_A.md`）与定稿自检时使用本模板。按任务性质保留对应分析区块，确保字段完整且直接兼容 `evan-build`。

## 二、定稿前企业级门禁清单

定稿交用户确认前逐条打勾核实，缺项直接补进 `PLAN.md`：

1. **根因或二三阶推演闭环**
   - 修复类是否找到了最本质根因并有代码/复现证据？
   - 新增/优化类是否写透了跨模块、App 体验、系统复杂度与长期维护成本的二三阶影响？
2. **复用与最小改动**
   - 是否先检查了项目内可复用代码？
   - 每个新增函数/层/依赖是否都有“现有做法为何行不通”的硬理由？
3. **文件强相关**
   - 拟改文件清单里是否存在顺手优化、无关格式化或超出本次需求的文件？若有立即移出至“延后观察项”。
4. **跨模块协作与安全边界**
   - 端到端输入→处理→成功/失败状态是否闭环？
   - 同事负责的上下游模块接口、存量数据、缓存、配置默认值是否全部向后兼容？
   - 每个阶段是否都能独立验收且安全回滚？
5. **PR 就绪与流程合规**
   - 若启用了方案 B，是否已将 `PLAN_A.md`、`PLAN_B.md` 及 `HANDOFF_SECOND_OPINION.md` 清理干净，仅保留正式 `PLAN.md`？
   - `PLAN.md` 是否存放在仓库外本地路径，确保后续 PR 零规划草稿污染？
   - 顶部 `状态`、`执行方式`、参考分支与四列进度表是否完整，可直接衔接 `evan-build`？
